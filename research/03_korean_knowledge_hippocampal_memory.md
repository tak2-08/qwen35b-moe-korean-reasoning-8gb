# 3편. 한국어 지식 붙이기와 "해마 기억"

> 모델이 돌아가긴 하는데 한국 이야기는 잘 몰랐다. 그래서 로컬 검색을 붙였고, 내친김에 뇌의 해마처럼 '한 번 보고 기억하는' 구조도 시제품으로 만들어 봤다.

작성: 2026-11-22 · 대상 PC: RTX 3070 8GB / RAM 16GB / Ryzen 5 5600X · 기반 모델: Qwen3.6-35B-A3B (IQ3_S)

## 한눈에 보기

| 무엇을 했나 | 결과 |
|---|---|
| 지식 검색 붙이기 (채팅 앱에 적용 완료) | 희귀한 한국 사실 질문 정답률 **11% → 72%** (120문항). 첫 글자까지 약 1.2초, 답변 속도 37~40 tok/s 유지 |
| 시험 객관식(수능·공무원·한국사 등)에 검색 붙이기 | **효과 없음** (52% → 52%). 객관식은 사실 하나를 아는 것보다 추론이 핵심이었음 |
| 새 구조 "해마 기억" (연구 시제품) | 새 사실을 **한 번만 보고** 34% 기억하면서, 다른 지식은 **98.6%** 그대로 유지. 기존 학습법은 30번 반복해도 24%, 다른 지식은 30%만 남음 |

## 1. 지식 저장소 (이 PC 안, 인터넷 없이 동작)

- **한국어 위키백과** 전체(2026-11-01판, 77만 문서 → 153만 조각, 4.5GB). 라이선스 CC BY-SA.
- **시험 기출(평가·연구용)**: Hugging Face에 공개된 자료를 받았어요.
  - 수능 국어 2025, HAE-RAE(한국사·일반상식·수능 사회탐구), KMMLU(한국사 등), 공무원 시험, 의사·치과·간호 국가고시(KorMedMCQA), 전문자격시험(KMMLU-Pro 2026).
- **검색 방식**: SQLite 전문검색 + 한글 2글자 단위 색인.
  - 질문에서 드문 단어 6개만 골라 검색해요. 흔한 단어 때문에 7.8초 걸리던 검색이 0.03~0.4초로 빨라졌어요.
  - 질문에 문서 제목이 그대로 나오면 그 문서의 첫 문단을 우선해요.

## 2. 검색이 정말 도움이 되나? (같은 문제, 조건만 바꿔 비교)

**객관식 시험 (생각 모드 끔, 과목당 25문항, 총 240문항)**

| 과목 | 기본 | 틀만 같은 대조군 | 검색 붙임 |
|---|---|---|---|
| 한국사 (HAE-RAE) | 84% | 88% | 88% |
| 일반상식 (HAE-RAE) | 80% | 76% | 72% |
| 한국사 (KMMLU) | 32% | 40% | 40% |
| 수능 국어 2025 | 28% | 56% | 64% |
| 전체 | 45% | 52% | 52% |

- 대조군은 질문 형식은 같고 자료만 비운 조건이에요. **검색 자체의 효과는 0이었어요.** 45%에서 52%로 오른 건 질문 형식이 달라져서였어요.

**희귀 사실 단답형 (동의보감 같은 실수 유형, 120문항)**
- 검색 없이: **11%** (13/120). 날짜나 숫자를 자신 있게 지어냈어요.
- 검색 붙임: **72%** (86/120).
- ⚠ 문항을 위키백과에서 만들었기 때문에 검색에 유리한 조건이에요. 실제 사용에서는 이보다 낮을 거예요.

## 3. 새 구조: "해마 기억" (Hippocampal binding memory)

**문제의식(사용자 아이디어):** 지금 LLM은 새 사실 하나를 배우려면 수천 번 반복해야 하고, 그때 모든 가중치가 바뀌어서 다른 지식이 망가져요(파국적 망각). 뇌는 해마가 새 기억을 한 번에 따로 저장하고, 비슷한 상황에서만 꺼내 써요.

**구조**
1. 본체(Qwen3.6)는 **완전히 얼려요.** 가중치를 하나도 바꾸지 않아요.
2. 새 사실을 읽을 때, 각 위치의 "생각 상태"(LM head 직전의 은닉 벡터)를 **열쇠**로 삼아 기억 칸 하나에 묶어요.
   - 열쇠는 평균을 빼고 화이트닝해서, 문장마다 다른 성분이 잘 드러나게 했어요.
3. **기억 내용(값)은 한 번에 써요.** 반복 학습 없이 "정답 토큰 방향 − 모델이 예상하던 방향" × α를 기록해요.
   - 예측이 틀린 만큼만 기록하는 방식이에요. 뇌의 "예측 오차 기반 학습"과 비슷해요.
4. 읽을 때는 지금 생각 상태와 가장 비슷한 열쇠를 찾아요.
   - 유사도가 문턱값(0.35)보다 낮으면 **기억 회로가 닫혀요.** 관련 없는 대화에는 아무 영향이 없어요.
5. (실험) MoE에서 같은 전문가가 켜진 기억 칸만 읽게 하는 조건도 시험했어요. 결과는 아래 표에 있어요.

**실험 설계**
- 모델이 알 수 없는 **가상의 사실 540개**를 만들었어요. 가상 회사의 창업자, 본사, 설립 연도, 가상 인물, 가상 섬 같은 것들이에요.
- 학습 문장과 **다른 표현의 질문**으로 시험했어요.
- 망각은 무관한 위키백과 300문단에서 쟀어요. 두 가지를 봤어요.
  - 원래 모델과 같은 답을 내는 비율(agree)
  - 문장 예측 손실(NLL)

| 방법 | 반복 | 새 사실 정답(완전 일치) | 무관한 글: 원래 답 유지 | 무관한 글 NLL 2.08 → |
|---|---|---|---|---|
| 기본 모델 | – | 0% | 100% | 2.08 |
| 일반 학습 (LoRA식 저랭크, 전 입력에 영향) | 1 | 3.1% | 54.5% | 3.54 |
| 〃 | 30 | 24.3% | **30.5%** | 5.76 |
| 기억 칸(PKM, 문턱 없음) | 30 | 7.6% | 52.8% | 3.75 |
| 전문가 주소 기억(EA, 문턱 없음) | 30 | 7.5% | 46.1% | 4.44 |
| **해마 기억 (경사하강 학습)** | 3 | 18.6% | 99.4% | 2.09 |
| 〃 | 30 | 23.0% | 99.3% | 2.09 |
| **해마 기억 (한 번 쓰기, α=100)** | **0 (한 번 봄)** | **33.6%** | **98.6%** | 2.20 |
| 〃 α=200 | 0 | 35.2% | 98.0% | 2.41 |

**해석**
- **망각을 거의 없앴어요.**
  - 일반 학습은 무관한 글의 답이 30%만 남았어요.
  - 해마 기억은 98~99%를 지켰어요.
  - 문턱이 없는 기억 칸(PKM, EA)도 망가졌어요. 열쇠 기반 문턱이 핵심이었어요.
- **반복이 필요 없었어요.** 한 번 쓰기만으로 일반 학습을 30번 반복한 것보다 많이 기억했어요(33.6% 대 24.3%).
- **"같은 전문가가 켜진 칸만 읽기" 조건은 이번 실험에서 추가 이득이 없었어요.** 내용 유사도만으로 이미 영역이 갈렸기 때문이에요. 국소 영역 아이디어는 "열쇠 유사도 + 문턱" 형태로 구현됐을 때 효과가 있었어요.
- **한계**
  - 정답률이 35% 근처에서 멈춰요. 질문이 엉뚱한 사실의 칸을 찾는 비율이 42%이기 때문이에요(같은 관계를 묻는 다른 회사 등).
  - 가상 사실, 짧은 답, 단일 모델 조건이에요.
  - 지금은 학습과 평가를 미리 뽑아둔 은닉 상태로 했어요. 채팅 중에 쓰려면 매 토큰 값을 바꾸는 엔진이 필요해요. 아래 "다음 단계"에 적었어요.

## 4. 채팅 앱에 반영된 것

- 바탕화면 「내 AI 시작」을 누르면 지식 검색이 함께 켜져요. 브라우저 → 지식 프록시(8080) → AI 엔진(8081)으로 연결돼요.
  - 모두 127.0.0.1이라 외부에서는 접속할 수 없어요.
- 답 끝에 `[출처: …]`가 붙어요. 끄려면 `config.ps1`에서 `$UseKnowledge = $false`로 바꾸면 돼요.
- 실제 화면 측정
  - 질문과 검색 자료 1,251토큰을 2.3초에 읽었어요.
  - 답변은 37~40 tok/s로 나왔어요.
  - 생각 모드를 끄면 첫 글자까지 1.2초예요.
- 남은 약점: 자료가 있어도 가끔 틀리게 덧붙여요. 시험 중 "향약집성방을 허준이 편찬"이라는 오류가 있었는데, 실제로는 세종 때 책이에요.

## 5. 다음 단계 (제안)

1. **해마 기억을 채팅에 연결하기.** 지금 만든 `bin/hm_host.exe`(은닉 상태와 전문가 경로 추출)를 확장해야 해요.
   - 매 토큰마다 기억에서 꺼낸 값을 LM head에 더해 주는 작은 서버가 필요해요. 계산량은 매우 작아요.
   - 그다음 "이거 기억해" 버튼으로 대화 중에 바로 한 번 쓰기 학습을 할 수 있게 해요.
2. **기억 찾기 정확도 올리기.** 지금은 58%예요. 질문 속 주어(회사·인물 이름) 위치의 상태를 열쇠에 함께 넣는 방법을 시도할 거예요.

## 6. 재현 방법

- 지식 저장소: `scripts\kb\build_wiki.py`, `crawl_news.py`, `kbcore.py`, `rag.py`
- 시험 평가: `scripts\kb\eval_kb.py`(객관식), `factqa.py`(단답). 결과는 `results\kb\`에 있어요.
- 해마 기억: `scripts\hm_host.cpp` → `bin\hm_host.exe`, `scripts\hm\facts.py` → `extract.py` → `train.py`. 결과는 `results\hm_runs.jsonl`에 있어요.
  - 예: `train.py --method bind --whiten 0.1 --gate 0.35 --oneshot 100 --epochs 1`
