# 6편. 시험 풀이 어댑터와 전문가 캐싱

> 드디어 실제로 쓸 만한 결과가 나온 편이다. 시험 문제를 단계별로 푸는 어댑터를 학습했고, 엔진 설정을 손봐서 생성 속도도 55% 끌어올렸다.

2026-11-24 · RTX 3070 8GB / RAM 16GB / Ryzen 5 5600X · Qwen3.6-35B-A3B IQ3_S

## 결론부터

1. **시험 어댑터(c1a)**
   - 학습에 안 쓴 2027학년도 문제에서 단계별 풀이 정답률이 **24.2% → 52.5%**로 올랐다.
   - 사고 모드를 켠 원래 모델(48.3%, 문항당 약 2,970토큰)과 비슷하거나 조금 높은 점수를, 3분의 1도 안 되는 토큰으로 낸다.
   - 대신 바로 답하기(−6%p)와 일반 상식(HAE-RAE −4%p)은 떨어졌다. 그래서 **객관식 시험 문제가 들어올 때만 자동으로 켜지게** 채팅 앱에 넣었다.
2. **전문가 캐싱**: 엔진에 들어 있는 GPU 전문가 캐시를 내 PC에 맞게 조정했더니 생성 속도가 **초당 38토큰 → 59~60토큰(+55%)**이 됐다.
   - 정답률은 그대로다(925문항 기준 62.7% → 62.6%, 1문항 차이).
   - GPU 메모리가 시스템 RAM으로 넘치는 일도 없다.

## 학습 데이터

- 비공개 한국어 단계별 풀이 약 2,900개. 이 저장소에는 넣지 않았다. 풀이 형식은 네 가지로 섞었다: 정석 단계 / 오답 소거 / 단서 먼저 / 사고 모드 형식.
- 첫 학습 묶음(chunk 0): 448개 시퀀스, 22만 토큰.
- 평가는 2027학년도 문제로만 했고, 이 문제들은 학습에도 검색 자료에도 넣지 않았다. 한국어 벤치마크(HAE-RAE, KMMLU, 공무원, 2025 수능 국어, 925문항)도 평가에만 썼다.

## 학습하면서 부딪힌 문제들

| 문제 | 해결 |
|---|---|
| 일부 시험 문항이 4천 토큰 가까이 돼서 기록 도구 한계(2,048토큰)를 넘었다 | 1,500토큰 이하 문항만 평가에 썼다 |
| GPU 메모리가 모자라 시스템 RAM으로 넘쳤고, 1회차 학습이 1시간 넘게 걸렸다 | 토큰 수 기준으로 배치를 짜고, 전문가 출력을 반정밀도로 보관했다 |
| 선형 어텐션(DeltaNet)을 토큰 하나씩 계산해서 엄청 느렸다 | 64토큰 묶음 계산(WY 변환)으로 바꿨다. 결과는 기울기까지 1e-6 안쪽으로 같고, **약 40배 빨라졌다**(1회차 3.6시간 → 7분) |
| 일상 문장에서 원래 모델과 어긋났다: c0는 87.8%로 기준(92%) 미달 | 일상 문장 보호 가중치 4 → 12, 길이 64 → 128, 학습률을 낮췄다 → c1a **93.2%** |

## 실제 엔진으로 채점한 결과 (2027학년도 시험)

| 항목 | 기본 모델 | c0a | c0b | **c1a (채택)** | c1b |
|---|---|---|---|---|---|
| 바로 답하기 (300문항) | 62.7% | 60.0% | 58.0% | 56.7% | 57.3% |
| 단계별 풀이 (120문항) | 24.2% | 52.5% | 44.2% | 52.5% | 53.3% |
| 정답 형식으로 끝맺은 비율 | 26.7% | 93.3% | 90.0% | 89.2% | 90.8% |
| 같은 60문항: 단계별 풀이 | — | — | — | **53.3%** | 45.0% |
| 같은 60문항: 사고 모드 켬 | **48.3%** (2,970토큰) | — | — | 23.3%* | 31.7%* |
| 일상 문장 일치도 (기준 92%) | 100% | 약 90.6% | 87.8% | **93.2%** | 91.9% |
| 한국어 벤치마크 전체 | 62.7% | — | 61.1% | 61.3% | 60.7% |
| 2025 수능 국어 | 75.6% | — | 82.2% | 82.2% | 82.2% |

\* 어댑터에 사고 모드를 켜면 생각이 짧아져서(평균 600~700토큰) 오히려 나빠졌다. 이 수치는 예전의 엄격한 채점 기준으로 낸 것이다. 실제로 쓸 때는 시험 문제에 사고 모드를 끈다.

**솔직하게 말하면**
- 단계별 풀이 점수가 오른 데는 "풀이를 끝까지 마치고 정답 줄로 끝맺는 습관"이 크게 작용했다.
- 60문항에서 3문항 차이라, 추론력 자체가 확실히 올랐다고 하기엔 통계적으로 부족하다.
- 자신 있게 말할 수 있는 건 "같은 정확도의 답을 훨씬 짧고 빠르게 낸다"는 것까지다.

(이후 학습 묶음을 더 돌리고 표본을 120문항으로 늘린 최종 결과는 [기술 보고서](../REPORT.md)에 있다. 거기서는 63.3% 대 52.5%, p = 0.041로 차이가 통계적으로도 확인됐다.)

## 전문가 캐싱으로 속도 올리기 (`scripts/serve/bench_serve.py`, `results/serve_bench.jsonl`)

| 설정 | 생성 속도 (256토큰) | 1,024토큰 생성 | VRAM |
|---|---|---|---|
| 이전: 층 26개 CPU, 캐시 없음 | 38.0 | 35.9 | 7.0GB |
| KV 8비트 + 층 22개 CPU | 44.4 | — | 7.7GB |
| 층 32개 CPU + 캐시 2200MiB, CPU 분담 100% | 45.8 | — | 7.6GB |
| **층 32개 CPU + 캐시 2000~2200MiB, CPU 분담 80%** | **59.4~59.5** | **53.4** | 7.6GB |
| 위 설정 + 시험 어댑터 | — | 57.2 | 7.6GB |
| 전부 CPU + 캐시 4400MiB, KV 8비트 | 58.6 | — | 7.2GB |

- 캐시에 없는 전문가 중 20%는 GPU로 올려서 캐시가 계속 학습되게 하고, 80%는 CPU가 계산하게 했을 때가 제일 빨랐다. CPU 분담 70~90%는 차이가 없었다.
  - 100%로 하면 캐시가 처음 채워진 상태로 굳어 버려서 느려진다.
  - 1편에서 떠올렸던 "자주 쓰는 부위만 미리 올려 두기"를 엔진이 알아서 학습하며 하는 셈이다.
- 스레드 수, 프로세스 우선순위, 폴링 설정은 차이가 없었다.
- 배치를 2048로 하면 긴 문서 처리가 1,163 → 1,498토큰/초로 빨라지지만, VRAM이 7.9GB로 한계에 닿아서 쓰지 않았다.
- 채팅 앱에서 실제로 재 보니 일반 질문 초당 61토큰, 시험 문제 초당 62토큰(5초 안에 정답)이었다.

## 고민했지만 안 한 것

- **엔진 코드 수정(`llama.dll` 재빌드)**
  - 공식 서버의 보조 DLL이 MSVC 방식 C++ 함수를 `llama.dll`에서 가져다 쓴다. 그래서 MSVC/Windows SDK를 시스템에 깔지 않고는 호환되는 DLL을 만들 수 없다. 시스템을 건드리지 않는다는 원칙 때문에 하지 않았다.
  - 하고 싶었던 개선은 두 가지였다. 공용 전문가를 CPU 전문가 계산과 동시에 돌리기, 다음 층 전문가를 예측해서 미리 올리기. 예상 효과는 5~10% 정도.
- **확산 모델 초안(추측 디코딩)**: 전문가를 RAM에 두는 구조에서는 초안 토큰을 검증할 때 읽을 전문가가 늘어나서 손해다. MTP 추측 디코딩도 실측에서 더 느렸다.
- **SSD 선행 로딩**: 지금 모델(12.7GB)은 RAM에 들어가서 이득이 작다. 더 좋은 4비트 파일(17GB, RAM 초과)을 쓰게 되면 다시 볼 과제다.

## 채팅 앱에서 바뀐 것

- 캐시 설정과 시험 어댑터 경로를 설정 파일에 넣었다.
- 엔진은 어댑터를 강도 0으로 올려 둔다. 평소에는 꺼져 있는 셈이다.
- 프록시가 객관식 시험 문제(①~⑤)를 감지하면 그 요청에만 어댑터를 켜고 사고 모드를 끈다(`rag_proxy.py`, `think_policy.py`).
- 채택한 어댑터는 4.6MB다.
- 학습 쪽에서는 `qwen_torch.py`에 64토큰 묶음 DeltaNet 계산을 넣었다(학습 40배 가속).
