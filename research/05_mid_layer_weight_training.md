## 1. 왜 지난번 방법(직접 경로)은 실패했나

4차 끝에 시도한 첫 방법은, 각 층의 출력을 바꿨을 때 최종 답이 어떻게 변할지 **근사**(DFA식: 위층을 건너뛰고 바로 최종 오차를 보내기)로 학습하는 것이었어요.

| | 학습 중 예측 | 실제 엔진 |
|---|---|---|
| 새 질문 정답 | 10% | **1.9%** |
| 학습 문장 토큰 | 81% | 44% |
| 무관한 글 유지 | 80% | 68% |

- 위 층들(어텐션, Gated DeltaNet)이 바뀐 신호를 다시 섞기 때문에, 근사가 실제와 크게 어긋났어요.
- 근사를 다시 맞추며 반복할수록 더 나빠졌어요(학습 문장 32%, 무관한 글 41%). 그래서 중단했어요.

## 2. 해결: "전문가는 고정, 나머지는 정확히" 대리 모델

35B 모델은 8GB GPU에 다 올라가지 않아요. 하지만 무거운 부분은 256개 **라우팅 전문가**예요. 그래서 이렇게 나눴어요.

1. llama.cpp가 평소처럼 실행하면서, 각 층의 라우팅 전문가 **출력**만 꺼내 저장해요(`hm_host.exe`).
2. PyTorch로 나머지 전부를 다시 구현했어요. 28개 층의 어텐션, Gated DeltaNet(선형 어텐션), 정규화, 공유 전문가가 여기에 들어가요(`qwen_torch.py`).
   - 3비트 가중치를 그대로 풀어서 써요.
   - 층마다 체크포인트를 둬서 GPU는 **1.9GB**만 써요.
3. 이 대리 모델에서 공유 전문가의 LoRA를 **정확한 역전파**로 학습해요.
4. llama.cpp LoRA로 내보내 **원래 엔진**에서 채점해요.

**검증:** 대리 모델과 실제 엔진의 최종 출력 차이는 약 1%, 다음 토큰 일치율은 99.8~100%예요.
- 맞추는 데 필요했던 세부사항이 있었어요. q/k 헤드 복제 방식은 "tile"이어야 하고, q에 1/√128 배율을 걸어야 했어요. 다른 조합은 선형 어텐션 오차가 컸어요.

## 3. 사람처럼 공부하기 ①: 스스로 문제 만들어 풀기 (인출 연습)

학습 문장만 외우면 같은 문장은 잘 맞히지만, **다른 표현의 질문**에는 약했어요. 사람도 교과서만 반복해 읽기보다 스스로 문제를 내고 풀 때 더 잘 기억해요(시험 효과).

- 모델이 학습 문장만 보고 사실마다 질문 6개를 직접 만들었어요. 1,701개를 남기고 1,198개는 버렸어요(답에 정답 단어가 없거나 평가 질문과 똑같은 경우).
- 평가 질문은 모델에게 **한 번도 보여주지 않았어요.**

| (대리 모델 기준) | 자기 문제 없이 | 자기 문제 연습 |
|---|---|---|
| 새 질문 정답 | 6.6% | **14.8%** |
| 첫 토큰 정답 | 31.9% | 40.3% |
| 무관한 글 유지 | 90.8% | 90.8% |

**누출 검사:** 모델이 우연히 평가 질문과 비슷한 질문을 만들었을 수도 있어요. 그래서 평가 질문을 비슷한 정도로 나눠 따로 채점했어요.

| 평가 질문과 가장 비슷한 자기 문제의 유사도 | 문항 수 | 정답 |
|---|---|---|
| 0.5 미만 (확실히 다름) | 911 | 14.9% |
| 0.5~0.7 | 114 | 15.8% |
| 0.7 이상 (거의 같음) | 55 | 10.9% |

→ 향상은 누출이 아니에요. 전혀 다른 표현의 질문에서도 그대로였어요.

## 4. 사람처럼 공부하기 ②: 배운 상태로 다시 점검하기 (갱신 라운드)

대리 모델은 전문가 출력을 **고정**해요. 그런데 학습으로 신호가 바뀌면 실제 엔진에서는 라우팅과 전문가 출력도 바뀌어요. 그래서 대리 모델 예측(14.8%)과 실제(7.8%)가 벌어졌어요.

- 해결: 학습한 LoRA를 **실제 엔진에 얹은 채로** 전문가 출력을 다시 꺼내고, 그 위에서 이어서 학습해요.
- 확인: 다시 꺼낸 직후 대리 모델의 점수(7.9%, 유지 84.8%)는 실제 엔진(7.8%, 83.9%)과 거의 같았어요. 원인이 정확히 이것이었다는 뜻이에요.

| 실제 엔진 결과 | 새 질문 정답 | 첫 토큰 | 학습 문장 토큰 | 무관한 글 유지 |
|---|---|---|---|---|
| 원래 모델 | 0% | 12% | 28% | 100% |
| 4차 직접 경로 | 1.9% | 28.3% | 43.7% | 67.7% |
| s1 대리 모델 | 5.3% | 30.4% | 66.2% | 80.5% |
| r1 + 자기 문제 | 7.8% | 33.3% | 65.9% | 83.9% |
| r1b + 갱신 1회 | **24.3%** | **53.9%** | 77.7% | 81.5% |
| r1c + 갱신 2회, 재생 강화 | {R1C_ROW} |
| (참고) 3차 해마 기억, 한 번 쓰기 | 33.6% | – | – | 98.6% |

## 5. 한국어 지식 추가 (검색 지식으로)

"추가 학습"을 두 갈래로 나눴어요.
- **사실·문제·해설처럼 양이 많은 지식**은 가중치에 넣으면 지금 기술로는 망각이 커요(위 표의 "무관한 글 유지" 참고). 그래서 채팅 앱이 질문할 때마다 찾아 쓰는 검색 지식으로 넣었어요.
- **가중치 학습**은 위 연구처럼 적은 양을 깊게 정착시키는 데 써요.

| 저장소 | 내용 | 크기 |
|---|---|---|
| 시험 기출 (`study.db`) | 공무원 기출 11,301 + 해설 5,060, KMMLU 206,512(학습·개발용만), KMMLU-Pro 6,214, KorMedMCQA 7,488, CSAT-QA 1,123, HRM8K 8,011, 한국어 실생활 질문 7,768 | 220MB |
| 사전 (`dict.db`) | 위키낱말사전 82,476표제어, 그중 속어·은어·비표준어 537개 표시 | – |

- 공정한 평가를 위해 평가용 시험(HAE-RAE, KMMLU 시험용, 공무원 평가용, 2025 수능)은 넣지 않았고, 겹치는 문항 4,948개도 뺐어요.
- 사전 뜻은 "~ 뜻이 뭐야?"처럼 뜻을 물을 때나 속어일 때만 붙여요. 그렇지 않으면 "무슨", "치아" 같은 흔한 단어 뜻이 답을 흐렸어요.


## 6. 안전
- 새로 설치한 시스템 프로그램은 없어요. 모두 `<local>`와 `<local>` 안에 있어요.
- 학습은 GPU 약 2GB, 채팅 엔진이 꺼진 상태에서만 돌렸어요. 끝난 뒤 남은 엔진 프로세스가 없는지 확인했어요.
- 서버는 모두 127.0.0.1에서만 열려요.

## 7. 재현
- 전문가 출력 추출: `scripts\hm\extract_surr.py` (환경변수 `CACHE`, `SURR`, `TAG`, `LORA`)
- 대리 모델: `scripts\hm\qwen_torch.py`, 검증 `valid_torch.py`, `valid_stack.py`
- 학습·내보내기: `scripts\hm\train_surr.py --edit 12-39 --rank 16 --wd_bg 3 --export out.gguf --dump items.json`
- 자기 문제 만들기: `scripts\hm\gen_rehearsal.py` (`run_rehearsal.sh`)
- 갱신 라운드: `scripts\hm\refresh.sh 이전 다음 재생강도 에폭`
- 실제 엔진 채점: `scripts\hm\eval_mid.py adapter.gguf` → `results\mid_real.jsonl`
- 지식 저장소: `scripts\kb\build_study.py`, `build_dict.py`, `build_blog.py`
