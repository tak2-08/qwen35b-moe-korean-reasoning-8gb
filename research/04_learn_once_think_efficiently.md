# 4편. 한 번 듣고 배우고, 짧게 생각하기

> 사람은 한 번 들은 걸 기억하고, 쉬운 문제는 오래 고민하지 않는다. 이 두 가지를 이 컴퓨터의 모델에게 시켜 보면 어떨까 싶어서 해 본 실험들이다.

작성: 2026-11-22 · RTX 3070 8GB / RAM 16GB · Qwen3.6-35B-A3B (IQ3_S)

## 한눈에 보기

| 주제 | 결과 | 채팅 앱 반영 |
|---|---|---|
| 한 번 듣고 배우기 | 채팅에서 "기억해: …" 한 번 → 새 대화에서 3.9초 만에 정확히 답함. "잊어줘: …"로 삭제 | ✅ |
| 모델 자체(가중치) 학습, VRAM 한계 우회 | 실제 Qwen3.6의 마지막 층 전문가를 8GB GPU에서 학습 → llama.cpp LoRA로 내보내는 경로 완성. 단, 한 층만 고치면 "학습량 ↔ 망각" 줄다리기가 심함 | 연구 단계 |
| 사람처럼 효율적인 생각 | 이 PC의 3비트 모델은 길게 생각할수록 손해(30문항: 바로 답 16개·15초 / 끝까지 생각 13개·68초). → 기본은 바로 답하고, 계산·코드·분석만 짧게 생각 | ✅ |

## 1. 사람처럼 배우기: 해마(빠른 기억) + 피질(느린 정착)

뇌는 새 일을 해마에 **한 번에** 적어 두고, 잠자는 동안 천천히 피질로 옮겨요(상보적 학습 시스템, CLS). 그래서 이번에는 두 단계로 나눠 만들었어요.

### 1-1. 빠른 기억 (채팅 앱 적용 완료)
- "기억해: 우리 동네 단골 빵집은 새벽별 베이커리이고 사장님은 윤하람 씨야" → 0.7초 만에 저장해요. 학습을 반복할 필요가 없어요.
- **새 대화**에서 "내 단골 빵집 이름이랑 사장님 이름이 뭐였지?"라고 물으면, 3.9초 만에 "새벽별 베이커리, 윤하람 씨"라고 답하고 `[출처: 사용자가 가르쳐 준 기억]`을 붙여요.
- "잊어줘: 새벽별 베이커리"라고 하면 지워지고, 그 뒤에는 더 이상 답하지 않아요(확인함).
- 가르쳐 준 기억은 질문과 겹치는 단어가 1/3 이상이면 위키백과보다 먼저 쓰여요.
- 저장 위치: `<local>`. 이 PC 안에만 있어요.
- 3차 연구의 "해마 기억"(은닉 상태에 직접 묶는 방식, 한 번에 34% 기억·망각 1.4%)은 채팅 엔진을 새로 만들어야 연결할 수 있어요. 그래서 채팅에는 같은 원리를 문장 단위로 적용했어요. 한 번 쓰기, 비슷한 상황에서만 꺼내기, 다른 지식은 건드리지 않기, 이 세 가지예요.

### 1-2. 모델 자체를 학습시키기: "전부 VRAM에 올려야 한다"는 문제를 우회한 방법
**구조적 해결**
1. 아래 39개 층은 llama.cpp가 평소처럼 실행해요. 3비트로 압축돼 있고 대부분 RAM에 있어요.
2. 그때 마지막 층(39층) 전문가들이 받는 입력과 라우팅 정보를 꺼내 저장해요.
   - 새로 만든 `hm_host.exe`가 필요한 내부 텐서를 그대로 뽑아요.
   - 재구성 오차는 0.038이에요. llama.cpp의 실제 계산과 일치해요.
3. GPU에서는 **39층 전문가의 LoRA**(작은 보정 행렬)와 고정된 LM head만 학습해요. 1GB 남짓으로 충분해요.
4. 결과는 llama.cpp의 LoRA 어댑터 형식(`blk.39.ffn_down_exps.weight.lora_a/b`)으로 내보내요.
   - llama.cpp 코드를 확인해 보니, MoE 전문가용 LoRA(`build_lora_mm_id`)를 Qwen3.6에도 지원해요.
   - 그래서 원래 채팅 엔진에 `--lora`로 바로 얹을 수 있어요.
   - 35B 모델을 VRAM에 통째로 올리지 않고도 **실제 모델의 가중치를 고치는 경로**예요.

**결과 (가상 사실 540개, 다른 표현의 질문으로 시험, 무관한 위키백과 글로 망각 측정)**

| 방법 | 새 사실 정답 | 무관한 글: 원래 답 유지 |
|---|---|---|
| 39층 전문가 전부 학습 | 10.4% (10회) | **14.9%** (크게 망가짐) |
| 사실에 특화된 전문가 16개만 학습 (ESFT식 국소 학습) | 0.7% | 90.4% |
| 〃 + 평소 글 되새김(재생) | 0.6% | 97.3% |
| 전문가 전부 + 재생 | 7.1% | 81.8% |
| 특화 전문가 32개 + 강한 재생 | 2.7% | 95.4% |
| (참고) 3차 해마 기억, 한 번 쓰기 | **33.6%** | **98.6%** |

**해석**
- 가중치를 직접 고치면 "많이 배우면 많이 잊는" 줄다리기가 뚜렷했어요.
  - 국소 학습과 재생으로 망각은 막을 수 있었어요.
  - 대신 마지막 한 층만으로는 저장 용량이 거의 없었어요.
  - 선행 연구(ROME/MEMIT)도 사실이 중간 층에 저장된다고 보고해요.
- 뇌가 해마와 피질을 따로 쓰는 이유를 이 PC에서 숫자로 확인한 셈이에요.
  - 빠른 학습은 별도 기억 장치가 맡아야 해요.
  - 가중치 정착은 여러 층에 걸쳐 천천히, 재생과 함께 해야 해요.
- **다음 단계:** 중간 층까지 학습하려면 Qwen3.6의 선형 어텐션(Gated DeltaNet)을 PyTorch로 다시 구현해야 해요.
  - 계획은 이래요. 층 단위로 GPU에 올렸다 내리고(스트리밍), 해마 기억에 쌓인 내용을 밤에 재생해 여러 층의 특화 전문가 LoRA로 정착시켜요.

## 2. 사람처럼 효율적으로 생각하기

**측정 (같은 30문항: 한국어 수학 12, 한국사·법·경제 객관식 18)**

| 방식 | 정답 | 평균 토큰 | 평균 시간 | 생각이 한도(4096)에 걸려 잘림 |
|---|---|---|---|---|
| 바로 답 | **16/30** | 563 | **15초** | 0 |
| 짧게 생각 (Chain-of-Draft식 메모 생각) | 16/30 | 2,108 | 56초 | 8 |
| 끝까지 생각 (기존 기본값) | 13/30 | 2,587 | 68초 | 11 |

- 이 PC의 3비트 모델은 길게 생각할수록 맴돌다 한도에 걸렸어요. 정확도도 오르지 않았어요.
- Chain of Draft 논문은 토큰을 7.6%까지 줄인다고 보고했어요. 하지만 이 모델은 "짧게 생각하라"는 지시를 생각 단계에서 잘 따르지 않았어요(토큰 19% 감소에 그침).
- 표본이 30문항이라 크지 않아요. 그래도 방향은 일관됐어요.

**채팅 앱에 반영한 규칙 (사람의 직관/숙고, System 1/2)**
- 기본은 **바로 답하기**예요. 인사, 사실 조회, 가르쳐 준 기억이 여기에 해당해요.
- 계산·풀이·코드·분석·비교·확률처럼 숙고가 필요한 질문만 **짧게 생각**해요. 이때 "핵심 메모로만, 답이 정해지면 즉시 끝내라"는 지침을 붙여요.
- 생각 한도는 4096에서 2048토큰으로 줄였어요.
- 이 규칙을 적용한 뒤 측정한 시간이에요.

| 질문 | 바꾸기 전 | 바꾼 뒤 |
|---|---|---|
| 사실 조회(측우기) | 26초 | **3.5초** |
| 가르친 기억 질문 | 20초 | **3.9초** |
| 간단한 계산 | 44초 | 25초 (정답 유지) |

- 설정 파일에서 직접 생각 모드를 켠 경우는 그 설정을 그대로 따라요.

## 3. 안전
- 새로 설치한 시스템 프로그램은 없어요. 모두 `<local>`와 `<local>` 안에 있어요.
- 학습은 GPU 메모리 약 3GB를 썼어요. 채팅 엔진이 꺼진 상태에서만 돌렸어요.
- 서버가 모두 127.0.0.1에서만 열려요.

## 4. 재현
- 39층 내부값 추출: `scripts\hm\extract_l39.py` (`bin\hm_host.exe`, 환경변수 `HM_CAPTURE`)
- 전문가 LoRA 학습·내보내기: `scripts\hm\train_l39.py --experts 16 --wd_bg 1.0 --export out.gguf`
- 생각 방식 비교: `scripts\kb\think_eval.py` → `results\kb\think.jsonl`
- 채팅 규칙: `<local>`, `rag_proxy.py`, `kb\rag.py`
